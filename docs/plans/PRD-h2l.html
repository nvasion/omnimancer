Problem statement

One model does everything in an omnimancer session today: design, exploration, edits, verification. Three costs follow.

  1. Frontier tokens are spent on mechanical edits. Both the interactive loop and the headless loop send every turn, including "replace this string in this file", to the session model.
  2. Small and local models are unusable for agent work. They fail when asked to explore and design. They do well when handed exact instructions, and nothing in omnimancer produces exact instructions for them.
  3. Nothing checks the result. A run ends when the model stops calling tools or says DONE. No criteria, no score, no second opinion.

The pieces for a two-tier flow already exist; nothing connects them, and one is built the wrong way for concurrency (verified 2026-09-20, HEAD d17b9f8):

  • An isolated worker loop exists. cli/subagent.py::SubAgentRunner.run has its own context, a tool allowlist, a model override, a capped loop, and parent-tagged events. But it mutates the shared provider's model attribute, never appends to its own history, runs only from /subagents run, and prints to a panel. Two concurrent runs on different models would clobber each other.
  • The concurrency-safe way to run a second model exists. core/prompt_enhancer.py copies a provider config with model_copy(update={"model": ...}), calls ProviderFactory.create_provider, and uses an isolated context. The initializer's cache key includes the model, so one provider with two models yields two instances. Nothing generalizes this.
  • No plan, story, or task type exists. The workflow orchestrator is instantiated on every engine start and never driven; its steps wrap Python callables.
  • No parallelism exists. No asyncio.gather in the package. Approval prompts block stdin through asyncio.to_thread(input).
  • Two loops, no shared turn. The codebase map says it outright: headless reimplements the agent loop and changes usually land in both files.
  • Only tool-capable providers can execute. Headless has no marker fallback. ollama, cohere, perplexity, and claude-code report no tool support. An openai-compatible alias pointed at Ollama's OpenAI endpoint works today.
  • The gate is single and shared. AgentEngine.execute_with_approval is the only path to a write, a command, or a web call on both loops. Workers inherit permission rules, hooks, approval, and hard-restricted paths for free.
  • Observability is already per-agent. agent_context is ContextVar-based, so it survives asyncio.gather; every tool event carries agent and parent ids; the Fleet TUI renders subagent rows as children.
Precedence gotcha the flags must respect. Env beats CLI flags beats stored config. apply_env_overrides runs inside provider initialization after session overrides and assigns unconditionally, so OMNIMANCER_<PROVIDER>_MODEL silently beats --model.

What it is

A run has three roles and one loop.

High tier
Principal

Reads the repo with the read tool set, writes a short design, submits a backlog of stories through submit_plan. Stories carry absolute paths, exact old and new strings or full file content, exact commands, acceptance criteria, an optional verify command, and dependencies.

Low tier
Worker pool

One story per worker on its own provider instance with its own history. Tools are Edit, Write, Bash, plus Read scoped to the story's files. Returns a diff and the verify output.

High tier
Judge

Deterministic checks first. Then the high model scores the diff and verify output against the criteria through submit_verdict. Never sees the worker's narration. Below threshold goes back with feedback, then an escalation policy applies.

Both surfaces run the same package. TUI: /h2l <goal> with models from the h2l config block. Headless: omn -p "<goal>" --h2l --high <ref> --low <ref> [--low <ref> ...].

/subagents is unchanged and kept. H2L's worker runner fixes the subagent runner's seven gaps; re-basing the subagent runner on it is a follow-up, not part of this PRD.

Goals and non-goals

Goals

  • A user runs a multi-file task where the high model plans, one or more low models execute, and the high model judges, from either surface, with the same package.
  • Workers never explore. Story quality is the lever, and the planner is held to it.
  • Every story is scored before it counts. The user sees per story: model, attempts, score, diff, tokens; and totals by tier.
  • Headless runs are resumable at story granularity and keep the existing exit-code and stream-json contracts.
  • No change to security, permission, or approval behavior. No change at all when the feature is not enabled.

Non-goals

Automatic model selection or routing. Nested H2L. Per-worker git worktrees (stories sharing a file serialize instead). Replacing /subagents. Judging with any model other than the high one. A marker-protocol fallback for non-tool providers. TUI checkpoints.

Design

1. Config block and model refs

New optional Config.h2l next to enhancement. Absence disables the feature. Added to the migration passthrough key list so it survives v1 to v2 migration.

class H2LModelRef(BaseModel):
    provider: str   # key of Config.providers, registered name or alias
    model: str

class H2LConfig(BaseModel):
    enabled: bool = True
    high: H2LModelRef
    low: List[H2LModelRef]                 # non-empty, ordered pool
    max_parallel: int = 2
    max_retries: int = 2                   # judge send-backs per story
    pass_threshold: int = 80               # 0..100
    worker_tools: List[str] = ["Edit", "Write", "Bash"]
    allow_worker_read: bool = True         # Read limited to story.files
    escalation: Literal["high", "block", "ask"] = "ask"
    plan_approval: bool = True
    worker_max_iterations: int = 15        # planner may raise per story, cap 30

Ref grammar: <entry>:<model>; a bare <model> resolves against default_provider. Resolution runs after provider initialization so the env pass cannot rewrite a tier. It copies the provider config with the new model and calls the factory. It never touches engine.providers or current_provider. Errors:

  • unknown entry: H2L: provider entry 'x' is not configured (see /providers)
  • non-tool provider: H2L: provider 'ollama' does not support tool calling; use an openai-compatible alias pointed at its OpenAI endpoint (see docs/provider-setup.md)

Both tiers are validated before any model call. Flags override config field by field and never persist.

2. Plan and story model

class Story(BaseModel):
    id: str                       # "S1"..; unique
    title: str
    instructions: str             # executable without exploration
    files: List[str]              # absolute paths the worker may touch
    acceptance: List[str]         # testable criteria
    verify: Optional[str] = None  # shell; exit 0 required when present
    depends_on: List[str] = []
    max_iterations: Optional[int] = None

class Plan(BaseModel):
    goal: str
    design: str
    stories: List[Story]

validate_plan(plan, cwd): unique ids; every dependency resolves; no cycles; every path absolute and under the working directory; stories sharing a file without a declared edge get an implicit edge in plan order so two workers never edit one file concurrently. Failure text names the story and the rule.

3. Planner

Fresh high-model instance, isolated context seeded with a system message, never the session chat. Tools: Read, Glob, Grep, Bash through the normal gate, plus submit_plan whose schema is Plan. Write and Edit are absent and refused if called.

The pinned planner prompt states: workers cannot see the repository and will not explore; every story must be executable from its text alone; absolute paths; exact old and new strings for edits, full content for new files; a verify command whenever a test or lint can prove the story; dependencies for shared files; stories small enough for a few tool calls; submit through submit_plan only. Project instructions are included through the existing loader with its "not system authority" banner.

Self-check turn. After the first submission the planner receives its plan back with "re-read each story for missing exact strings and unresolved references; resubmit" and must submit again. The second submission is the plan. Cap 20 iterations; no submission by then means plan_failed, exit 1, no worker starts.

4. Worker

  • Provider instance from section 1; the parent provider's model is never read or written.
  • Context seeded with the worker prompt plus the story as system; every turn appended, native tool history when the provider supports it.
  • Tool definitions are worker_tools plus Read when allowed. Enforced at execution: any tool outside the set, or a Read outside story.files, returns H2L: tool X not permitted for this story and is never dispatched.
  • Every dispatched call goes through execute_with_approval unchanged. cancelled aborts the worker. Repeat guard reuses RepeatedCallTracker.
  • On exit: git diff scoped to the story's files, the verify command run through the gate with output and exit code captured, and out-of-scope files from git status --porcelain.
class WorkerReport(BaseModel):
    story_id: str; worker: H2LModelRef; attempt: int
    success: bool; narrative: str
    tool_log: List[ToolLogEntry]          # name, arguments, result[:2000]
    diff: str; verify_output: Optional[str]; verify_exit: Optional[int]
    files_outside_scope: List[str]
    usage: UsageTotals

The worker prompt states: follow the story exactly; do not explore; do not read files you were not given; if an Edit old string does not match, stop and say so; when finished, run the verify command if given and report in one paragraph.

5. Judge

Deterministic stage, no model call, in order; the first hit fails the attempt:

  1. verify exit non-zero: verify failed (exit N)
  2. out-of-scope files: modified files outside story scope: ...
  3. empty diff on a story with files: no changes made

Model stage: fresh high instance, isolated context, input is the story, the acceptance list, the diff, and the verify output. Not the narrative or tool log.

class Verdict(BaseModel):
    story_id: str; attempt: int
    score: int                 # 0..100
    passed: bool
    failures: List[str]        # one per failed criterion
    feedback: str              # instructions a worker can act on without context
    judge: Literal["deterministic", "model"]

Pass means passed and score >= pass_threshold. The judge prompt states: score the diff against the criteria only; verify output is evidence; do not reward length or explanation; list each failed criterion; write feedback as instructions.

6. Orchestrator

  • DAG from section 2. Ready stories run under asyncio.gather with a semaphore of max_parallel. One means fully serial.
  • Round-robin assignment in pool order. A retry goes to the next model with the verdict's feedback prepended as Feedback from review of attempt N:.
  • After max_retries: high runs the story on the high model with the full tool set, judged deterministically only; block marks the story blocked and dependents skipped; ask prompts in the TUI and behaves as high in headless.
  • Approval callback wrapped in an asyncio.Lock, each preview prefixed [H2L S3 · gateway:qwen3-8b]. Restored on exit.
  • Identity: run id h2l-<session_id>; planner and judge under h2l-high-<hex>; each worker attempt under h2l-<story_id>-<hex>, all with the run as parent. Session events carry provider, model, story, attempt, status, and verdict score. The Fleet TUI needs no change.
  • Rate limit after the engine's retry handler is exhausted: stop with rate_limited, checkpoint kept.
  • Presenter protocol so the logic is written once: approve_plan, on_story_start, on_report, on_verdict, on_escalation, on_done.

7. TUI surface

  • /h2l <goal>: plan, design paragraph plus story table, prompt [a]ccept [d]rop <id> [e]dit <id> [c]ancel, run, summary table. Edit opens $EDITOR when set, otherwise a multi-line prompt; the edited plan is re-validated.
  • /h2l plan <goal> stops after the plan and holds it. /h2l run executes it. /h2l status, /h2l config. Config edits through /config set h2l.<field>.
  • One row per active worker (story, model, current tool, elapsed) above the streaming panel through activity_provider. Never a second live region.
  • The parent conversation gets one assistant message: the summary. Worker transcripts never enter the session chat.
  • Completion and help entries added.

8. Headless surface

New plain options on the single click command (it must stay a command, not a group; orchestrators parse omn -p --help).

FlagTypeOverrides
--h2lflagenables the mode
--high REFstrh2l.high
--low REFstr, repeatablereplaces h2l.low when given at least once
--h2l-parallel Ninth2l.max_parallel
--h2l-retries Ninth2l.max_retries
--h2l-threshold Ninth2l.pass_threshold
--h2l-escalationhigh or blockh2l.escalation
--h2l-plan-onlyflagstop after the plan

Any H2L flag without --h2l is a usage error. --h2l with no resolvable high or an empty pool exits 1 with H2L: no high model configured (set h2l.high or pass --high).

Without --dangerously-skip-permissions workers cannot write, so the run prints the plan and exits 0 with result subtype h2l_plan_only. --h2l-plan-only does the same regardless. That is the dry-run mode.

stream-json adds one event type with seven subtypes; tool events gain story_id and agent_id during a run:

{"type":"h2l","subtype":"plan","session_id":"…","plan":{…}}
{"type":"h2l","subtype":"story_start","session_id":"…","story_id":"S1","attempt":1,"provider":"gateway","model":"qwen3-8b","agent_id":"h2l-S1-a1b2c3d4"}
{"type":"h2l","subtype":"story_report","session_id":"…","story_id":"S1","attempt":1,"success":true,"files_changed":["/abs/p.py"],"verify_exit":0}
{"type":"h2l","subtype":"story_verdict","session_id":"…","story_id":"S1","attempt":1,"score":92,"passed":true,"failures":[],"judge":"model"}
{"type":"h2l","subtype":"story_blocked","session_id":"…","story_id":"S3","reason":"retries_exhausted"}
{"type":"h2l","subtype":"story_skipped","session_id":"…","story_id":"S4","reason":"dependency_blocked:S3"}
{"type":"h2l","subtype":"done","session_id":"…","passed":5,"blocked":1,"skipped":1,"cancelled":0}

The final result blob gains h2l: {stories, usage_by_tier}; each tier carries input, output, cached tokens, and cost. Exit codes: 0 all passed; 1 error before or during planning; 3 finished with any blocked, skipped, or cancelled story; 4 rate-limited and resumable. The notify command and turn_complete hook fire once at the end with "h2l": true added. The events test locks the new shapes.

9. Checkpoint and resume (headless)

Sibling file <session_id>.h2l.json in the checkpoint directory with the same session-id guard and atomic replace. Holds the plan, per-story state, attempts, last verdict, and usage by tier; rewritten after every verdict. omn --resume <id> continues from the first story not passed, blocked, or skipped; a story that was running restarts from its last completed attempt. No sibling means the ordinary headless resume. Clean exit deletes both files; exit 3 and 4 keep them.

Acceptance

  1. Unit, models and refs. Ref grammar including bare and colon-in-model forms; config defaults; plan validation rejects cycles, duplicate ids, unresolved dependencies, paths outside the working directory, and adds the implicit shared-file edge in plan order; resolution after a simulated env override still yields the flag's model; a non-tool provider fails with the exact alias message; the resolved provider is never the one in the engine's dict.
  2. Unit, planner. Mocked provider returns submit_plan; a Write call is refused; the self-check turn happens and the second submission wins; a missing submission yields plan_failed; the session chat is never touched.
  3. Unit, worker. History accumulates across three turns; a hallucinated tool and an out-of-scope read return the permitted-error and never reach the gate; cancel aborts; diff scoped to the story's files; verify captured; out-of-scope files populated; the parent provider's model is byte-identical before and after.
  4. Unit, judge. Each deterministic rule short-circuits with no model call; the model prompt excludes narrative and tool log; threshold boundary (79 fails, 80 passes); feedback lands in the retry prompt.
  5. Unit, orchestrator. DAG order with implicit edges; two providers on different models run concurrently under a parallelism of two without clobbering; approval callback serialized and prefixed; round-robin and next-model retry; all three escalation policies; skip on blocked dependency; events carry the right parent id; checkpoint rewritten after each verdict.
  6. CLI. Plan table and accept, drop, edit, cancel; the summary is the only message added to the parent conversation; flags, config fallback, usage error without --h2l; plan-only exit 0; exit codes 0, 1, 3, 4; the seven subtypes and the result block; sibling checkpoint round-trip and story-granular resume; config file byte-identical after a flag run.
  7. Prompts. sha256 pins for the three prompts.
  8. Regression. Full test suite and the four lint gates green; the subagent tests untouched and green.
  9. Live. In this repository, a three-to-five story task with a frontier high model and a local 7B-class low model behind an openai-compatible alias: every story passes or is blocked with a named reason; no file outside any story's list is modified; the summary shows high-tier output tokens below the same task run single-model. Repeat headlessly with stream-json and skipped permissions; kill it after the second verdict; resume finishes with exactly the remaining stories started.

Rollout and risk

  1. Phase 1 · serial MVPfeat: commit producing 0.3.0. Sections 1 to 5, section 6 with parallelism forced to 1 and escalation limited to high or block, section 7 without the activity rows, sections 8 and 10. Acceptance 1 to 4, 6 to 8, and the serial half of 9. Proves the loop end to end without touching concurrency.
  2. Phase 2 · parallel poolParallelism above 1, approval lock and prefix, next-model retry, escalation ask, per-worker activity rows, completion and help entries. Acceptance 5 and the concurrent assertions in 9.
  3. Phase 3 · resilienceSection 9 checkpoint and resume, usage by tier in the TUI summary, Ollama native tool support if not already landed. The resume half of 9.

Risks

  • Story quality is the whole game. Vague stories mean blind workers fail and the judge loop burns tokens. Mitigated by the self-check turn, the pinned planner prompt, and plan-only mode so a user can inspect before spending. Measure first-attempt pass rate on a ten-task benchmark in this repo before release; target at least 70 percent with a 7B-class low model.
  • Stale old strings. Story N+1 may cite text story N changed. The implicit edge orders them, but both were written against the original file. Scoped read plus the feedback loop catch it; if the benchmark shows it often, the planner prompt gains "write later stories against the post-edit file".
  • Judge bias. The judge grades diffs, never narration, and deterministic checks run first. Hand-assess judge and user disagreement on the benchmark; target under 15 percent.
  • Approval fatigue. Six workers writing three files each is eighteen prompts. The plan gate, existing accept modes, and permission rules cover it; the prefix makes each prompt attributable.
  • Behaviour change surface. None when the block is absent and the flag is not passed.
  • Deploy. omnimancer only. Factory containers pick it up on the next pinned version bump; consuming the result block is optional.
